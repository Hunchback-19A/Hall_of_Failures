GitHub release checklist (manual upload)
=======================================
Block copolymer self-assembly design prototype

Use this when you create a repository or release on the GitHub website.
Check items off as you go (mark [x] when done).

See also: user_guide.md (project overview, CLI, references).


Before you upload
-----------------
[ ] Decide public vs private. If public, treat copyright carefully
    (do not ship licensed PDFs — see "What not to upload").
[ ] Confirm the project runs on a fresh machine:
      pip install -r requirements.txt
      python -m unittest discover -s tests
[ ] Remove temporary folders if present:
      build/, __pycache__/, _extract/, _ref_meta/, local .pyd/.so binaries
[ ] Confirm .gitignore excludes build/, __pycache__/, *.pyd, *.so, *.dll, etc.
[ ] Write a short README.md (can point to user_guide.md) with install + examples
    Include the run command and where the .out and .result.json files go
    (user_guide.md section 6.4).
[ ] Set a version you are happy with (e.g. tag v0.1.0;
    package __version__ is in polymer_engine/__init__.py)
[ ] This exhibit is GPL-3.0-or-later (LICENSE is the GPL text).
    Paste hall_of_failures_root_notices.txt into the Hall of Failures
    root LICENSE and README so the rest of that repo stays MIT.
    Keep third_party/pscfpp/LICENSE and PROVENANCE.txt.
    Keep the copyright lines on Minnesota's files and on files written
    for this exhibit (Copyright (C) 2026 Disquietude, GPL-3.0-or-later).
    The Windows program bin/pscf_rpc.exe is part of that GPL work.
    Its PSCF source is the rest of third_party/pscfpp. GSL 2.8 and
    FFTW 3.3.10 are linked into the exe; name them as PROVENANCE.txt does.
    Educational physics code is not permission to ship others' PDFs


What to include in the GitHub package
-------------------------------------
[ ] polymer_design/          (all Python + data/*.json, including
                              instrument/, run_limits.json, and
                              data/examples/periodic_lamellar.json)
[ ] polymer_engine/          (Python sources; omit compiled _*.pyd / _*.so
                              unless you intentionally ship wheels)
[ ] benchmarks/
[ ] tests/
[ ] cpp_core/                (headers/sources + README.md + SCFT_MDE_EXTENSION.md)
[ ] setup_cpp_core.py
[ ] requirements.txt
[ ] user_guide.md
[ ] github_release_checklist.txt   (this file)
[ ] README.md + LICENSE + .gitignore
[ ] third_party/pscfpp/   (vendored PSCF subset, LICENSE, PROVENANCE.txt,
                          bin/pscf_rpc.exe, and ntfs-incompatible-paths.zip
                          if present)
[ ] Optional: CITATION.cff or a short "How to cite this software" note


What NOT to upload by default
-----------------------------
[ ] Do NOT upload the References/ PDF tree to a PUBLIC repo unless every
    file is redistributable (most books/papers are not). Prefer the APA list
    in user_guide.md section 9 and keep PDFs offline.
[ ] Do not upload personal paths, API keys, or unpublished experimental data
[ ] Do not upload build/ artifacts or __pycache__/
[ ] Avoid shipping large binary extensions unless you document
    OS / Python version matrices


GitHub website steps (manual)
-----------------------------
[ ] 1. Create a new repository (name, description, public/private)
[ ] 2. Upload or push the included files
       (drag-and-drop works for small trees; git is cleaner for updates)
[ ] 3. Paste README content so the landing page explains install + examples
[ ] 4. Add topics (e.g. block-copolymers, scft, polymer-physics, python)
[ ] 5. Create a Release: Releases -> Draft a new release -> tag v0.1.0
[ ] 6. Release title example:
       v0.1.0 — Educational block copolymer design prototype
[ ] 7. Release notes (short): features (evaluate / design / validate /
       simulate SCFT / run a filed request), limitations (1D SCFT,
       toy phase-field, four PSCF cells), link to user_guide.md
[ ] 8. Attach a source zip only if needed; usually the tag's
       auto-generated archive is enough
[ ] 9. Verify: clone/download in another folder and run the commands
       from the README, including
       python -m polymer_design run polymer_design/data/examples/periodic_lamellar.json
       Confirm the terminal prints the report path and the result path.


Suggested release notes skeleton
--------------------------------
## Summary
- Educational block copolymer self-assembly toolkit (chiN, morphology map, domain scaling).
- Inverse design ranking via local monomer grids.
- Solvers: analytical, toy 1D phase-field, minimal 1D AB SCFT; optional
  periodic diblock SCFT via Minnesota pscf_rpc (Windows exe included).
- Traceable scientific reports (Interpretation + Reason).
- `run` files a JSON request as a human report plus a JSON result.
  Human and AI requests use the same checks. Batch ceiling 1000.
- Optional `visualize` export (an Avogadro cube). The frame is the cell
  edge. Above the box, a red letter A and a blue letter B name polymer A
  and polymer B. Those letters are not atoms of the polymer.
  Illustrative sketches are labeled as sketches. PSCF concentrations
  are kept only with --keep-concentration. Picture batches are 100.

## Limitations
- Not a production SCFT / DSA code.
- The educational SCFT solver is 1D AB only; phase-field is a toy demo.
- Optional pscf_rpc covers four periodic diblock cells and is still not a process model.
- Analytical morphologies follow an educational classical map.
- `run` ranks only converged PSCF cells. Declaring client "ai" does not
  change validation or the 1000-candidate ceiling.

## Install
pip install -r requirements.txt
python -m polymer_design evaluate --polymer PS-b-PMMA
python -m polymer_design run polymer_design/data/examples/periodic_lamellar.json
